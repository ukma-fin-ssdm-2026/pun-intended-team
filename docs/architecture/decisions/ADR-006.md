# ADR-006: Event Import Sources

**Status:** Proposed

## Context

- FR-008 asks for events imported from external listing services, naming Concert.ua as an example. The import (CMP-03, ADR-001) so far ran one adapter on a sample feed, as no provider offers us an API.
- Without an API, the import reads public pages (R-001), so it must stay within each site's robots.txt and load, and parse the schema.org `Event` data the sites publish for search engines rather than their markup (ADR-003: cheerio).
- Applicants are matched per event session. The same event imported from two providers becomes two catalog events, and the applicants of one copy never meet those of the other.
- Matching needs every venue on the map (FR-012); not every provider gives coordinates.
- The sources were compared on 2026-11-03: [event import sources research](../research/event-import-sources.md).

## Decision

1. **Two sources: ArtWizard and Karabas.**

   | Source | Decision | Why |
   |---|---|---|
   | ArtWizard (artwizard.io) | In, for the course demo only until ArtWizard permits it (decision 9) | Lectures, exhibitions, workshops and other events ticket operators do not sell; JSON-LD with coordinates |
   | Karabas (kyiv.karabas.com) | In | The ticket operator: concerts, theatre, cinema, sport, festivals, clubs; one section page carries the full JSON-LD of about 20 events |
   | Concert.ua | Out | Sells the same concerts as Karabas, so importing both would split applicants; needs one request per event; `@type` is `MusicEvent` for everything. `ConcertUaEventProvider` and its sample feed are removed |
   | Kontramarka | Out | No schema.org Event data; `Crawl-delay: 10` |

2. **Access per robots.txt.** ArtWizard: the sitemap `sitemaps/events.xml`, then each Kyiv event page in the catalog window; never `/api/`, `/internal/` or the image CDN `/cdn-cgi/`. Karabas: the seven Kyiv section pages; never `/ajax.php`, and not the sitemap, which lists mostly past events. Every request names the service in its User-Agent, waits at least 1 s after the previous one to the same site (Karabas `Crawl-delay: 1`) and is retried with backoff on network errors, 429 and 5xx. The HTTP client refuses a disallowed path before sending it.
3. **Failures never stop a run.** A page that cannot be fetched or rendered is kept as a skipped record with its reason (FR-015); a provider whose list cannot be read fails its own run only, and the other provider's run goes on (REL-003, FR-014).
4. **Categories** come from ArtWizard's type tags and from the Karabas section, not from `@type`: Concerts, Exhibitions, Talks, Workshops, Cinema, Theatre, Stand-up, Sports, Festivals, Parties. Toloka is renamed Volunteering; it and Open days have listings only. Events with no matching category (e.g. children's events, excursions, circus) are skipped.
5. **Times.** Both sources write Kyiv wall-clock time with a wrong offset (ArtWizard `19:00Z` for 19:00, Karabas `21:00+02:00` for 19:00). The adapters read the digits as Europe/Kyiv time. An end that is missing or not after the start is the end of the start day in Kyiv. ArtWizard shows 00:00 when the organizer gave no time (e.g. "Я бачу, вас цікавить пітьма", which Karabas sells at 18:00), and a midnight start would show a wrong time and move the matching rounds anchored to it, so an ArtWizard event that starts at exactly 00:00 Kyiv time is skipped as having no start time (FR-015). Karabas writes its `endDate` midnights without the shift, so they are read as given:
   - the next midnight means no end is given: the end of the start day;
   - a time later the same day, shifted like the start, is a real end (`21:00–23:00+02:00` is 19:00–21:00);
   - a later midnight is a run of shows from the start date to the day before it (e.g. "Тигролови", 3–12 November): only the first show is imported, ending with its day, and the run is logged.
6. **Images are linked, not copied.** `events.image_url` stores the provider's image URL and `events.source_url` its event page, which credits the provider and leads to tickets. The import never downloads an image.
7. **Geocoding.** A venue without coordinates (every Karabas venue) first takes those of the saved venue with the same name and address; otherwise the `Geocoder` port looks it up, implemented with Nominatim at most once a second, within Kyiv. Its data is © OpenStreetMap contributors under the ODbL, so the attribution must appear where the app shows these coordinates. A venue it cannot find is skipped with the event.
8. **Duplicates across providers are not merged.** With a single ticket operator they are rare; an event both providers list stays twice.
9. **ArtWizard's terms are a risk until it permits the import.** Its public offer ([offer.pdf](https://artwizard.io/files/offer.pdf)) says the platform's databases may not be used without its permission (§11.1), and that event materials come from the organizers (§11.2). Permission was requested from support@artwizard.io on 2026-11-03; status: **pending**. Until it is granted, ArtWizard is imported for the course demo only, with these mitigations: the Kyiv slice only, at least 1 s between requests, images as links, and a link to the ArtWizard page on every event. If ArtWizard refuses, its adapter is unbound in `ImportInfraModule` and its events are removed. Karabas' public offer has no such clause.

## Alternatives

| Option | What it does better | Why not |
|---|---|---|
| Karabas and Concert.ua | More concerts | Most are the same concerts: duplicate events and split applicants; Concert.ua needs 1 + N requests per section |
| Merge duplicates across providers | One event per real event | Needs fuzzy matching of titles, venues and times; out of scope until duplicates show up in practice |
| Download images to our storage | Images survive the provider removing them | Storage and rights we do not have; ArtWizard's robots.txt disallows its image CDN |
| Paid geocoder (Google, Mapbox) | Better hit rate on informal addresses | A key and a bill for a few dozen new venues a week; Nominatim's limit is enough at Kyiv scale |
| Football club sites for sport | More matches | One adapter per club; deferred to its own issue, Karabas `/sport/` covers matches for now |

## Consequences

- The catalog has real Kyiv events from two sources; a third is a new adapter class and a line in `ImportInfraModule` (FLEX-003).
- A run takes minutes, not seconds: one ArtWizard page a second, plus the Nominatim lookups for new venues.
- A redesign of either site breaks its adapter; the saved pages in `tests/unit/fixtures/providers/` pin the expected shape, and a broken adapter shows up as skipped records or a failed run, not as wrong events.
- Imported image URLs can stop working when the provider removes them; the app shows its gradient for an event without an image.
- **Known limitation: runs of shows.** For now a Karabas run (a play on every day from 3 to 12 November) is imported as its first show only, so users cannot apply for the later dates. The full schedule, one session per day ([matching](../mechanisms/matching.md), rule 9), is left for #366.
- **Known limitation: Karabas sections are not our categories.** `/clubs/` also lists talks, board-game nights and wine tastings, which land in Parties. Refining the category from `@type` or the title is left for #366.
- ArtWizard may withdraw from the catalog if its permission is refused (decision 9).
- **Reconsider if** ArtWizard refuses or grants permission, a provider offers an API or a partner feed, if the same event regularly shows up from both sources, or if Nominatim's hit rate on Karabas addresses turns out too low.
