# ADR-006: Event Import Sources

**Status:** Proposed

## Context

- FR-008 asks for events imported from external listing services, naming Concert.ua as an example. The import (CMP-03, ADR-001) so far ran one adapter on a sample feed.
- ArtWizard gave the team access to its events API on 2026-11-03 (decision 9). The other sources offer no API, so for them the import reads public pages (R-001): it must stay within each site's robots.txt and load, and parse the schema.org `Event` data the sites publish for search engines rather than their markup (ADR-003: cheerio).
- Applicants are matched per event session. The same event imported from two providers becomes two catalog events, and the applicants of one copy never meet those of the other.
- Matching needs every venue on the map (FR-012); not every provider gives coordinates.
- The sources were compared on 2026-11-03: [event import sources research](../research/event-import-sources.md).

## Decision

1. **Two sources: ArtWizard and Karabas.**

   | Source | Decision | Why |
   |---|---|---|
   | ArtWizard (artwizard.io) | In, through its events API, with ArtWizard's permission (decision 9) | Lectures, exhibitions, workshops and other events ticket operators do not sell; coordinates for every venue |
   | Karabas (kyiv.karabas.com) | In | The ticket operator: concerts, theatre, cinema, sport, festivals, clubs; one section page carries the full JSON-LD of about 20 events |
   | Concert.ua | Out | Sells the same concerts as Karabas, so importing both would split applicants; needs one request per event; `@type` is `MusicEvent` for everything. `ConcertUaEventProvider` and its sample feed are removed |
   | Kontramarka | Out | No schema.org Event data; `Crawl-delay: 10` |

2. **Access.** ArtWizard: its events API, `GET https://api.artwizard.io/events` with the Kyiv events whose occurrences touch the catalog window, 20 per page, every page of the answer; no event pages are crawled. The key is the secret `ARTWIZARD_API_KEY`: it is sent in the request URL only, and every logged URL and error shows it as `REDACTED`. Karabas, per its robots.txt: the seven Kyiv section pages; never `/ajax.php`, and not the sitemap, which lists mostly past events. Every request names the service in its User-Agent, waits at least 1 s after the previous one to the same site (Karabas `Crawl-delay: 1`) and is retried with backoff on network errors, 429 and 5xx. The HTTP client refuses a path the site's robots.txt disallows before sending it.
3. **Failures never stop a run.** A record that cannot be used is kept as a skipped record with its reason (FR-015); a provider whose list cannot be read (an ArtWizard API page that does not answer, a missing key) fails its own run only, and the other provider's run goes on (REL-003, FR-014).
4. **Categories** come from ArtWizard's `type` and from the Karabas section, not from `@type`: Concerts, Exhibitions, Talks, Workshops, Cinema, Theatre, Stand-up, Sports, Festivals, Parties. Toloka is renamed Volunteering; it and Open days have listings only. Events with no matching category (e.g. children's events, excursions, circus) are skipped.
5. **Times.** Both sources write Kyiv wall-clock time with a wrong offset (ArtWizard `18:00Z` for 18:00, Karabas `21:00+02:00` for 19:00). The adapters read the digits as Europe/Kyiv time. An end that is missing or not after the start is the end of the start day in Kyiv. An ArtWizard event lists its occurrences (`event_occurrences_data`), each of one of three kinds:
   - `date_from` equal to `date_to`: a start without an end, so the event ends with its day;
   - a later `date_to`, the same day or after midnight: a real end;
   - 00:00 to 23:59:59, on the same day or a later one: no time given. ArtWizard writes 00:00 when the organizer gave no time (e.g. "Я бачу, вас цікавить пітьма", which Karabas sells at 18:00), and an exhibition's run this way.

   The adapter imports the earliest occurrence with a time that starts in the catalog window, and logs an event with more than one occurrence in it. A midnight start would show a wrong time and move the matching rounds anchored to it, so an event whose only occurrences in the window have no time is skipped as having no start time (FR-015). Karabas writes its `endDate` midnights without the shift, so they are read as given:
   - the next midnight means no end is given: the end of the start day;
   - a time later the same day, shifted like the start, is a real end (`21:00–23:00+02:00` is 19:00–21:00);
   - a later midnight is a run of shows from the start date to the day before it (e.g. "Тигролови", 3–12 November): only the first show is imported, ending with its day, and the run is logged.
6. **Images are linked, not copied.** `events.image_url` stores the provider's image URL and `events.source_url` its event page, which credits the provider and leads to tickets. The import never downloads an image.
7. **Geocoding.** ArtWizard gives every venue's coordinates, so its venues are not looked up. A venue without coordinates (every Karabas venue) first takes those of the saved venue with the same name and address; otherwise the `Geocoder` port looks it up, implemented with Nominatim at most once a second, within Kyiv. Its data is © OpenStreetMap contributors under the ODbL, so the attribution must appear where the app shows these coordinates. A venue it cannot find is skipped with the event.
8. **Duplicates across providers are not merged.** With a single ticket operator they are rare; an event both providers list stays twice.
9. **ArtWizard permits the import, on conditions.** Its public offer ([offer.pdf](https://artwizard.io/files/offer.pdf)) says the platform's databases may not be used without its permission (§11.1), and that event materials come from the organizers (§11.2). Permission was requested on 2026-11-03 and granted the same day by Vlad Lisovyk, ArtWizard's founder, by email, together with access to the API, within the scope of the request and on three conditions:
   1. Nearby stays a non-commercial study project: no ads, no paid features, and the data is not passed to third parties.
   2. The permission lasts for the duration of the study project, which ends by **2026-12-10**; the team asks again before then.
   3. ArtWizard is told in advance before the import changes how often it collects.

   Commercial use needs a separate agreement. The import keeps to the Kyiv slice, links images instead of copying them, and links every event to its ArtWizard page. If the permission ends, the adapter is unbound in `ImportInfraModule` and its events are removed. Karabas' public offer has no such clause.

## Alternatives

| Option | What it does better | Why not |
|---|---|---|
| Karabas and Concert.ua | More concerts | Most are the same concerts: duplicate events and split applicants; Concert.ua needs 1 + N requests per section |
| Merge duplicates across providers | One event per real event | Needs fuzzy matching of titles, venues and times; out of scope until duplicates show up in practice |
| Keep crawling the ArtWizard sitemap and event pages | No key to keep secret | One request per event instead of one per 20; the type tags had to be dug out of the page's Next.js data; the API is what ArtWizard permitted |
| Download images to our storage | Images survive the provider removing them | Storage and rights we do not have; ArtWizard's robots.txt disallows its image CDN |
| Paid geocoder (Google, Mapbox) | Better hit rate on informal addresses | A key and a bill for a few dozen new venues a week; Nominatim's limit is enough at Kyiv scale |
| Football club sites for sport | More matches | One adapter per club; deferred to its own issue, Karabas `/sport/` covers matches for now |

## Consequences

- The catalog has real Kyiv events from two sources; a third is a new adapter class and a line in `ImportInfraModule` (FLEX-003).
- A run takes seconds for ArtWizard (4 API pages for 74 Kyiv events on 2026-11-03) and a little longer for Karabas, plus the Nominatim lookups for new venues.
- A change of the ArtWizard API or a redesign of the Karabas site breaks its adapter; the saved responses in `tests/unit/fixtures/providers/` pin the expected shape, and a broken adapter shows up as skipped records or a failed run, not as wrong events.
- Without `ARTWIZARD_API_KEY` the ArtWizard run fails and Karabas still runs. On staging the key is an optional secret: a deploy without it succeeds, and only the import's ArtWizard run fails.
- Imported image URLs can stop working when the provider removes them; the app shows its gradient for an event without an image.
- **Known limitation: runs of shows.** For now a Karabas run (a play on every day from 3 to 12 November) is imported as its first show only, so users cannot apply for the later dates. The full schedule, one session per day ([matching](../mechanisms/matching.md), rule 9), is left for #366.
- **Known limitation: Karabas sections are not our categories.** `/clubs/` also lists talks, board-game nights and wine tastings, which land in Parties. Refining the category from `@type` or the title is left for #366.
- **Known limitation: ongoing exhibitions.** An exhibition that runs through the window without opening hours, with only a 00:00–23:59:59 run in it (e.g. "Іванів ковчег. Простір свободи", open until 29 November), is skipped for now as having no start time; so is one written as a single occurrence from a past opening to its last day ("Нелінійний простір", 29 October 18:30 to 29 November), as having no occurrence in the window. On 2026-11-03 that was 15 of the 74 ArtWizard events. Importing them as multi-day events needs a decision on opening hours, left for #366.
- **Known limitation: events stored before the API.** Events an earlier run stored that the adapter now skips, such as "Я бачу, вас цікавить пітьма" at 00:00, stay in the catalog: the import updates and adds events, but never removes them. They pass with their dates.
- ArtWizard leaves the catalog when its permission ends, by 2026-12-10 unless it is extended (decision 9).
- **Reconsider if** ArtWizard's permission ends or a commercial use is planned, another provider offers an API or a partner feed, if the same event regularly shows up from both sources, or if Nominatim's hit rate on Karabas addresses turns out too low.
