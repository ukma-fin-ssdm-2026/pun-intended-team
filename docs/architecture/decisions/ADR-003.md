# ADR-003: TypeScript for the Event Import Service

**Status:** Accepted

## Context

The event import service (CMP-03) fetches and normalizes events from external providers, possibly by scraping (R-001). Python was proposed as a simpler language for this kind of work.

## Decision

CMP-03 stays in **TypeScript / NestJS**, in the same codebase and image as the main server (ADR-001). Scraping uses cheerio for static HTML and Playwright for JS-rendered pages.

## Alternatives

| Option | What it does better | Why not |
|---|---|---|
| Python | Slightly richer scraping and data-processing libraries | Needs a second schema definition next to Prisma, which can drift from the first; pg-boss is Node-only, so `event.changed` would be written into its internal tables by hand; the event model is duplicated across languages; a second image, toolchain and CI pipeline; ADR-001's merge trigger no longer applies |

## Consequences

- One schema, one set of types, one pipeline for both processes.
- **Reconsider if** normalization needs ML or NLP (e.g. auto-classifying scraped events into categories, Ukrainian text processing) — there Python's ecosystem clearly wins.
