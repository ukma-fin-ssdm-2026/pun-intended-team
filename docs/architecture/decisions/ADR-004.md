# ADR-004: Google-Only Sign-In for Now

**Status:** Accepted

## Context

Registration verifies a phone number with a one-time code sent through Telegram Gateway, with SMS as the fallback (FR-005, [authentication](../mechanisms/authentication.md)). Neither can be paid for yet ([external services](../../operations/external-services.md)): a Telegram Gateway top-up is at least $100, and the TurboSMS account is still being verified. Without a code a phone number cannot be verified, and a password only makes sense next to a verified number, since it signs in and is reset with that number.

## Decision

**Until codes can be paid for, people sign up and sign in with Google only.**

- `POST /auth/google/register` checks the Google ID token and creates a pending account with the Google sign-in method. `complete-registration` runs the age check as before (SAFE-001).
- The routes for phone registration, password sign-in, password reset, setting a password and linking Google are removed. `AuthService` keeps their logic, the lockout, verification codes and messaging, with their unit tests, so restoring the routes brings them back.
- The app's code and password screens are commented out in `app/src/phone-auth/`.
- An account's phone number is null. The phone columns, the `password` sign-in type and the verification code table stay, so the phone flow needs no down-migration to return.
- There are no development accounts. People sign in with their own Google account; the administrator is an account on the team's shared email whose `role` is set by hand.
- The git tag `phone-auth-baseline` marks the last state in which the phone flow worked end to end.

FR-005, SEC-007 and SEC-008 stay the target.

## Alternatives

| Option | What it does better | Why not |
|---|---|---|
| Phone codes to our own number only | No code changes | Nobody else can register |
| Keep the phone routes, switched off by config | Coming back is one setting | The spec, Swagger and MCP tools would show routes that never work |
| Delete the phone code | Less code to read | Restoring it means digging it out of git history |

## Consequences

- A mutual match reveals only the contacts people add to their profile.
- One person can register several accounts with several Google accounts (TM-15).
- iOS and Android need native Google sign-in, so the app runs as a development build instead of Expo Go.
- **Reconsider when** paid code delivery is funded, at the latest before the app is published.
