# Nearby client (Expo)

Mobile and web client for the Nearby API, built with [Expo](https://expo.dev) and [Expo Router](https://docs.expo.dev/router/introduction/) (TypeScript). It shows the event catalog under a five-tab bar, filters it by search, category, day and district, and shows an event's page, for a signed-in user or a guest. Sign-up and sign-in with Google, sign-out and the profile screens (setup, edit, contacts) use the API; so do the report sheet and the admin pages; the other screens run on mock data for now (`src/mocks/`), and the API hooks in `src/hooks/` are kept for connecting them.

## Getting started

Once, install the dependencies and create `.env`:

```bash
cd app
npm install
cp .env.example .env   # then adjust the values if needed
```

Then run the API and the client in two terminals:

```bash
# terminal 1, in the repository root: the API on http://localhost:4100
CORS_ORIGINS=http://localhost:8081 npm run dev

# terminal 2: the client on http://localhost:8081
cd app && npm run web
```

`CORS_ORIGINS` lets the web client, served from `http://localhost:8081`, call the API from the browser; without it the browser blocks the requests. To open the client on a phone, see [Running on a phone](#running-on-a-phone). See the root [README](../README.md) for the API itself.

## Running on a phone

1. Connect the phone and the computer to the same Wi-Fi network.
2. Find the computer's IP address: `ipconfig` on Windows (IPv4 Address), `ipconfig getifaddr en0` on Mac.
3. Run the API as in [Getting started](#getting-started).
4. Open the client:
   - Development build: see [Development build](#development-build). Signing in with Google needs it.
   - Expo Go: run `npm start` and scan the QR code. Expo Go has no Google sign-in, so the Google button only shows a snackbar; the catalog works as a guest.
     - On WSL, Expo puts the WSL IP address into the QR code by default and the phone cannot connect; run `REACT_NATIVE_PACKAGER_HOSTNAME=<IP> npx expo start` instead.
     - On iPhone, Expo Go opens the project only when Expo Go and Expo CLI are logged in to the same Expo account (free, expo.dev): Profile → Log in in the app, `npx expo login` in `app/` on the computer.
   - Phone browser: run `npx expo start --web`, start the API with `CORS_ORIGINS=http://localhost:8081,http://<IP>:8081` and open `http://<IP>:8081`.

The client calls the API on the same host it was opened from, port 4100, unless `EXPO_PUBLIC_API_URL` is set.

On WSL, the phone cannot reach servers inside WSL by default. Once:

1. Add to `%USERPROFILE%\.wslconfig`:

   ```ini
   [wsl2]
   networkingMode=mirrored
   ```

2. Run `wsl --shutdown` and reopen WSL.
3. In PowerShell as administrator:

   ```powershell
   Set-NetFirewallHyperVVMSetting -Name '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -DefaultInboundAction Allow
   ```

Without mirrored mode (Windows 10 and older Windows 11, where `Set-NetFirewallHyperVVMSetting` is missing):

1. Find the WSL IP address: `hostname -I` in WSL (the first address).
2. In PowerShell as administrator:

   ```powershell
   netsh interface portproxy add v4tov4 listenaddress=<IP> listenport=8081 connectaddress=<WSL IP> connectport=8081
   netsh interface portproxy add v4tov4 listenaddress=<IP> listenport=4100 connectaddress=<WSL IP> connectport=4100
   New-NetFirewallRule -DisplayName "Nearby dev" -Direction Inbound -Protocol TCP -LocalPort 8081,4100 -Action Allow
   ```

3. The WSL IP address may change after a restart: run `netsh interface portproxy reset` and repeat both `portproxy` commands (not the firewall rule).

The warning `error while installing React Native DevTools ... libnspr4.so` in WSL can be ignored.

### Development build

Google sign-in on a phone uses [`@react-native-google-signin/google-signin`](https://react-native-google-signin.github.io/docs/install), a native module that Expo Go does not have, so the app runs as a development build: Nearby's own app with `expo-dev-client`, which loads the JavaScript from `npm start` like Expo Go does. The native folders `ios/` and `android/` are generated by the build and ignored by git.

The Google OAuth clients live in the team's Google Cloud project (APIs & Services → Credentials), and the API's `GOOGLE_CLIENT_IDS` lists all three:

| Client type     | Settings                                               | Goes to                                                  |
| --------------- | ------------------------------------------------------ | -------------------------------------------------------- |
| Web application | Authorised JavaScript origin `http://localhost:8081`   | `EXPO_PUBLIC_GOOGLE_CLIENT_ID`                           |
| iOS             | Bundle ID `ua.nearby.app`                              | `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID`                       |
| Android         | Package `ua.nearby.app`, the SHA-1 of the EAS keystore | nothing in the app; Google matches the package and SHA-1 |

The builds run on [EAS Build](https://docs.expo.dev/build/introduction/) in the team's Expo project (`nearby`, profiles in [`eas.json`](eas.json)). EAS signs Android builds with the project's keystore (SHA-1 `98:47:F6:9B:E3:63:B2:C9:5A:E3:54:2D:7F:78:A5:55:87:30:0B:3C`; `npx eas-cli credentials -p android` shows it). A local `npx expo run:android` build is signed with a debug key instead, which needs an Android client of its own.

`.env` is not uploaded to EAS, so the build reads the two `EXPO_PUBLIC_GOOGLE_*` values from the EAS environment of its profile. They are set for `development`; to set or change one, for example for `preview`:

```bash
npx eas-cli env:set preview --name EXPO_PUBLIC_GOOGLE_CLIENT_ID --value <web client id> --visibility plaintext
npx eas-cli env:set preview --name EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID --value <iOS client id> --visibility plaintext
npx eas-cli env:list preview
```

Build and install:

- Android: `npx eas-cli build --profile development --platform android`, then open the link EAS prints on the phone.
- iOS: an EAS build for an iPhone needs a paid Apple Developer account; without one, use Xcode and CocoaPods (`brew install cocoapods`) and run `npx expo run:ios` (`--device` for a connected iPhone), which reads `.env`.

Rebuild after adding a native package or changing `app.json`, `app.config.ts` or `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID`. Otherwise run `npm start` and open the installed app, as with Expo Go.

## Admin pages

Administrators review reports, ban users and manage categories at `/admin`, e.g. `http://localhost:8081/admin`, in a browser on a computer; on a phone the page asks to open it on a computer. To make an account an administrator, see [Local database](../README.md#local-database) in the root README, then sign in again. Reports from the mock posts and matches go to the usernames `iryna`, `artem`, `maksym` and `olena`, so they reach the API only when an account has that username.

## Environment variables

| Variable                           | Example                                     | Purpose                                                                                                                                                                 |
| ---------------------------------- | ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `EXPO_PUBLIC_API_URL`              | `http://localhost:4100`                     | Base URL of the Nearby API; optional, detected when not set                                                                                                             |
| `EXPO_PUBLIC_GOOGLE_CLIENT_ID`     | `1234567890-abc.apps.googleusercontent.com` | Google OAuth web client id: Google's button on the web, and the audience of the ID tokens on iOS and Android; without it nobody can sign up or sign in                  |
| `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID` | `1234567890-def.apps.googleusercontent.com` | Google OAuth iOS client id; `app.config.ts` turns it into the URL scheme of the iOS build, so rebuild after changing it. Without it the iOS build has no Google sign-in |

`EXPO_PUBLIC_*` values are inlined into the JavaScript bundle, so they must never contain real secrets. The client needs no token setting: signed out, it gets a guest token from `POST /api/v1/auth/guest`; signed in, it sends the account's access token and renews it with the refresh token, which it keeps in the keychain or keystore on a phone and in `localStorage` on the web. `.env` is ignored by git; `.env.example` is committed.

## Checks in CI

The client steps of the "CI passed" job ([`ci.yml`](../.github/workflows/ci.yml)) run on every pull request and must pass to merge. They run these checks in `app/`, after `npm ci`:

| Check                | Run it locally                                                       |
| -------------------- | -------------------------------------------------------------------- |
| Lint                 | `npm run lint`                                                       |
| Types                | `npm run typecheck`                                                  |
| Formatting           | `npx prettier --check .` (fix with `npm run format`)                 |
| API types match spec | `npm run api:types`, then `git diff --exit-code src/api/schema.d.ts` |

After any change to the API spec (`docs/api/openapi-generated.yaml`), run `npm run api:types` and commit the regenerated `src/api/schema.d.ts`; otherwise the last check fails in CI. The client has no tests, and its dependencies are not audited in CI.

## UI kit

The screens are built from the [Figma design](https://www.figma.com/design/SxoD0EfoWYmJ5zehxl7rtX/nearby?node-id=0-1) with [NativeWind](https://www.nativewind.dev/) (Tailwind classes in React Native).

- **Tokens.** `src/styles/tokens.ts` holds the Figma variables under their Figma names, so `brand/coral` becomes the class `bg-brand-coral`. Text sizes are `text-title`, `text-body`, `text-caption` and so on; the weight comes from the font family: `font-inter`, `font-inter-medium`, `font-inter-semibold`, `font-inter-bold`; the logo uses `font-alice`. Change a colour or text style here, not in components.
- **Components.** `src/components/ui/` has the Figma components: `Button`, `IconButton`, `TextField`, `SearchField`, `Chip`, `Toggle`, `EventCard`, `EventCardSkeleton`, `FilterChip`, `TabBar`, `Overlay` (modal layer with the backdrop for dialogs and sheets), `Sheet` (the "01 Шторка" bottom sheet over `Overlay`), `RadioOption` (the option rows of 03 and П1.1), `SelectChip` (the coral chips of П1.2 and Д1.1), `Snackbar` (confirmations and errors at the top of the screen, always 64 px tall with a one-line note) and `CoralGradient` (the radial gradient of the catalog header and of covers without an image).
- **Icons.** `<Icon name="calendar" size={16} color={…} />`; `name` is typed, so a wrong name fails `npm run typecheck`. To add an icon, export it from Figma as SVG into `assets/icons/`, keep the file as exported, and add it to the map in `icon.tsx`. Most Figma icons are the Solar icons at another size; where Figma draws one with a heavier stroke than the scaled icon (for example the 16 px tick with a 2.2 px stroke), the Figma export is added under its own name instead of scaling the Solar one.
- **`className` only on React Native components.** NativeWind applies classes to React Native's own components (`View`, `Text`, `Pressable`, `ScrollView`, `TextInput`, `Image`…), not to `Animated.View` from Reanimated, `expo-image` or `react-native-svg`. Give those a `style`, or put the classes on a `View` inside them.
- **Glass.** Elements with a background blur in Figma use `Glass` (`src/components/ui/glass.tsx`) with the Figma corner radius, fill, border and blur radius. The web gets the exact Figma CSS (`backdrop-filter: blur(radius / 2)`), iOS the system blur. Android 12 and newer blur only what is inside a `BlurTargetView` passed as `blurTarget` (the card and event covers); without one, and on older Android, the glass shows its fill alone.
- **Shadows.** Use the `boxShadow` strings from `shadows` in `tokens.ts`; they render on iOS, Android and web. Take the radius and spread from the Figma effect itself: Figma's CSS export writes half the radius into `drop-shadow()`. Do not use SVG filters for shadows: they do not render on every platform.
- **Navigation.** Links follow the Figma prototype: the tabs open Т1–Т4, the bell opens Т5 Сповіщення, the avatar the profile tab, the categories arrow the Д1 Фільтри sheet, and a card the event page; when the search and filters leave no events, the catalog shows 01.3 "Нічого не знайшли", whose "Скинути фільтри" clears both. On the event page the main button opens 03 Запит на компанію, or 04 Пошук компанії when the user is already in the matching (02.1, shown with the development switch), and the address row and the map preview the map tab; the organizer row the organizer page (its cards open the event page). A guest has no bell or greeting, the avatar opens the sign-in dialog (02.2), and the event page and the Метчі, Оголошення and Профіль tabs open the sign-in dialog (02.2). Dialogs and sheets close on a backdrop tap. The matching flow follows the prototype too: the request sheet opens 04, which shows 05 after 4 s; "Ще" on 04 opens the 04.1 menu, whose "Змінити побажання" opens 03 on the event page and "Вийти з підбору" the 04.2 dialog ("Вийти з підбору" returns to the event page, "Залишитися" to the menu); on 05 dragging the arrow along "Прийняти" accepts and the cross declines, and 1.8 s after the answer the Метчі tab opens as Т2.2, with its toast after accepting or declining; there the mutual card and "Написати" open the 06 safety sheet over 07. On Т5 "Прочитати все" clears the unread dots (Т5.2), and on Т5.1 "Олена хоче піти з тобою" opens the Д4 sheet, whose "Прийняти" opens 07 and "Не цього разу" closes it. Т5 "Це взаємно!" opens the 06 safety sheet over 07, whose "Зрозуміло" uncovers 07. Back on 05 and 07 and "Зрозуміло" after a report open the Метчі tab. On Т3 the search button opens Т3.3 Пошук оголошень in place of the header (the query filters the posts, its tabs switch only visually, and the back button returns to the feed); the "create post" row opens the inline editor (Д2), whose "+ Місце" opens Д2.1 Місце на мапі (the map drags under the pin; "Обрати місце" returns to the editor) and "Опублікувати" returns to the feed, "Хочу піти" on a post sends a request: the action reads "Запит надіслано" and the Т3.2 snackbar names the author; and "Ще" on a post opens the report flow; 04 "Створити оголошення" opens the tab with the editor. On the profile tab the "Про мене" and "Збережені" tabs under the name switch between Т4 and П6 (the favourite events), and the edit button opens П1, where "+ ще" opens the П1.2 Інтереси sheet (its "Зберегти" applies the choice) and "+ Додати соцмережу" the П1.1 sheet; and "Вийти з акаунта" the П5 dialog. In Д1 "Обрати дати" opens the Д1.1 calendar sheet (a day or a range, or a quick choice; "Застосувати" filters by it and returns to Д1) and "Поруч зі мною" the Д1.2 location dialog, whose "Дозволити" marks the chip (there is no location yet, so it does not narrow the list). On Т1 the filter button opens Д1 and the venue's events open the event page. Onboarding (В1–В3) is a swipe carousel: only the slides move, the step indicator and the buttons stay, and the dots and "Далі" page it; on В3 the Google button takes the place of "Далі", and "Увійти" on В1 and В2 pages to В3. On О1 the edit button opens О4 (its toggles switch locally; the logo picker has no design and does nothing; "Вийти з акаунта" opens the О4.1 dialog, whose "Вийти" opens В1 and "Залишитися" closes it), and "Нова", "Редагувати" and "Продовжити" open О2 (on О1.1 "Нова" and "Створити подію"), where the "Категорія" field opens its О2.1 list in place (picking a category closes it), whose "Чернетка" and "Опублікувати подію" return to О1, and "Скасувати" opens the О3 sheet. С1 "Спробувати ще раз" opens the catalog and "Переглянути збережені події" the profile on its "Збережені" tab, and С3 "Зрозуміло" returns to the screen that opened it. No prototype screen links to О1 or С1–С3 yet; open them from the gallery.
- **Sign-in.** Sign-up and sign-in are Google-only for now ([ADR-004](../docs/architecture/decisions/ADR-004.md)); the phone and password screens are commented out in `src/phone-auth/`, and the phone number is hidden from the profile screens. Without a stored session the app opens on В1 Онбординг. The Google button is on В3 and in the guest dialog (02.2); there is no separate sign-in screen. It sends the ID token to `signInWithGoogle`: a known account opens the catalog, and a Google account without a Nearby account (a `401`) goes to В5, which shows the Google account and asks for the date of birth and the terms. "Створити акаунт" sends `registerWithGoogle` and `completeRegistration`, which signs in, and goes on to В7 and В8. A `429` opens С3 Забагато спроб; other failures show a snackbar at the top. On iOS and Android the button is the Figma button with Google's mark and opens Google's account picker (a [development build](#development-build) only); on the web it is Google's own pill, since Google gives an ID token on the web only through its own button. The "Гість" switch in the gallery leads to В1 when nobody is signed in.
- **Motion.** Animations take their values from Figma's motion data and prototype (Smart Animate durations and easing) and run on Reanimated; with reduced motion they rest on their first frame or switch at once.
- **State.** `src/state/` holds client state shared between screens in small stores (`createStore`, over `useSyncExternalStore`): the mock session and the catalog filters, which the search, the category row and the filters sheet all change. Favourite events are one store too, so a heart toggled on a catalog card shows on the event page, on П6 and back; it starts with the three events П6 shows in Figma. Post likes (Ірина's post starts liked, as on Т3) and "Хочу піти" requests on the Оголошення tab are kept the same way.
- **Status bar.** Call `useStatusBarStyle('light')` on a screen with a dark top, `'dark'` otherwise; it applies when the screen gets focus.
- **Gallery and modes.** Run `npm run web` and open `http://localhost:8081/dev/components` to see every component and state. Its first section switches the mock session: guest or signed in, whether the catalog shows its skeleton for 1.5 s first (on by default, as in the prototype), whether the event page shows 02.1 "Ти вже в пошуку" (off by default), whether the Метчі tab is empty (Т2.1), whether the Оголошення tab is empty (Т3.1), whether Т5 shows the join request of Т5.1, and whether О1 has no events (О1.1). Its "Інші екрани" section opens О1 and С1–С3. It also shows the other titles of 07 ("Концерту бути!", "Вечір врятовано!", "Гірко!"). Catalog cards always show the default "Знайти компанію" button; the gallery shows the "У пулі" card. Open the catalog with the button there: reloading the page resets the switches. The route only works in development; in a production build it redirects to the catalog.
